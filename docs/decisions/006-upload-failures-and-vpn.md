# החלטה 006 — אבחון כשלי העלאה, ותוספות VPN בדפדפן

תאריך: 2026-08-18

## הקשר

בבדיקות מול מועצת בדיקה (1600000) העלאת ששת קובצי המצב"ת מהאתר נכשלה
שוב ושוב עם הודעה אחת:

```
שגיאה: Unexpected token '<', "<html><hea"... is not valid JSON
```

ההודעה נראית כמו באג באתר. היא אינה. משמעותה שבקשה כלשהי קיבלה **דף
HTML במקום JSON**, ו-`JSON.parse` נפל על התו הראשון — בלי לרמוז איזו
בקשה, באיזה שלב, או מי שלח את ה-HTML.

## מה נשלל, ואיך

הכשל שוחזר מהמחשב של המשתמש מול אותה רשות, עם אותם קבצים:

| נבדק | תוצאה |
|------|-------|
| ששת הקבצים מ-`try2` דרך Storage API | **כולם 200** (3.9MB, 8.6MB, 3.2MB, ועוד) |
| `fetchUploads('1600000')` | `200 JSON []` |
| RLS על `moe-uploads` ועל `moe_uploads` | עוברת (`is_super_admin()`) |
| מגבלת גודל / סוגי קבצים על ה-bucket | אין |
| העלאות multipart של 8/20/60MB | מגיעות ל-Supabase, מקבלות JSON |
| ה-bundle החי | URL נכון, מפתח באורך 46 |
| Service Worker | לא קיים |
| כללי הפניה ב-`netlify.toml` | רק SPA fallback |
| פרוקסי מערכתי ב-Windows | `ProxyEnable = 0` |
| העלאות אמיתיות מהאתר באותו יום | **שתיים הצליחו** (רשות 120) |

כלומר: הצד השרתי תקין לחלוטין, ואותה פעולה בדיוק מצליחה מפייתון על
**אותו מחשב ואותה רשת**.

### הפרט שהכריע

Netlify מחזיר `<!doctype html>`. ההודעה מתחילה ב-`<html><hea` — **בלי
doctype**. זו אינה תשובה של האתר אלא של משהו שיושב בדרך.

## הסיבה

שתי תוספות VPN מותקנות בכרום של המשתמש:

```
Browsec VPN          proxy, webRequest, declarativeNetRequest, <all_urls>
Windscribe Free VPN  proxy, webRequest, <all_urls>
```

תוספת כזו מנתבת את תעבורת **הדפדפן** דרך שרת משלה. כשהיא נתקלת במגבלה
— נפח בחשבון חינמי, או גוף בקשה גדול — היא מחזירה דף שגיאה HTML במקום
להעביר את הבקשה.

כל ממצא מתיישב עם זה:

- פייתון מאותו מחשב עובד — תוספות אינן נוגעות בו.
- אין פרוקסי מערכתי — הפרוקסי חי בתוך כרום.
- `Ctrl+Shift+R` לא עזר — רענון אינו מכבה תוספות.
- הדף נטען וההיסטוריה נטענת — בקשות GET קטנות עוברות.
- הכשל הוא על **הקובץ הראשון, 3.9MB** — ה-POST הגדול הראשון.

הפרט האחרון הוא המכריע: שום דבר לא נכשל עד שהגיעה בקשה של כמעט 4MB.

## ההחלטה

### 1. ההודעה אומרת איזה שלב נכשל

עד עכשיו שלוש נקודות כשל שונות הגיעו למסך כהודעה זהה: אחד מששת הקבצים,
שלב הרישום ב-`moe_uploads`, או טעינת ההיסטוריה בכניסה לדף. עכשיו
ב-[`src/lib/admin.ts`](../../src/lib/admin.ts):

```
שגיאה: העלאת קובץ 1/6 (GORMEY_KESHER_..., 3.9MB) — ...
שגיאה: רישום ההעלאה — ...
שגיאה: טעינת היסטוריית העדכונים — ...
```

ותשובת HTML מתורגמת להסבר: זו אינה תקלה באתר אלא חסימה בדרך, עם הצעה
לנסות בחלון סתר. `Failed to fetch` מתורגם לניתוק רשת.

**זה מה שסגר את האבחון** — עד שהתווית נוספה, לא ידענו אם נפל קובץ ואיזה.

### 2. לא עוקפים את ה-VPN

**הפתרון הוא לכבות את התוסף** (`chrome://extensions`), או לעבוד בחלון
סתר שבו תוספות מושבתות כברירת מחדל.

לא נבנה מעקף, משלוש סיבות:

1. הסף שבו התוסף חוסם אינו ידוע ואינו מתועד, וכל ערך שנבחר הוא ניחוש.
2. אי אפשר לאמת תיקון כזה מהצד שלנו — הוא קיים רק בדפדפן אחד.
3. עדכון גרסה של התוסף יכול להחזיר את התקלה בלי שנדע.

זו בעיה במחשב אחד, לא במערכת. **אצל סבא המסלול העיקרי הוא התיקייה
הנסרקת, שאינה עוברת בדפדפן כלל.**

## אם זה יחזור — שתי אפשרויות שנבדקו

### העלאה מחולקת (TUS)

ה-endpoint פעיל בפרויקט:

```
OPTIONS /storage/v1/upload/resumable  →  200
```

במקום POST אחד של 3.9MB, כ-20 בקשות של 256KB. סביר שיעברו — הבקשות
הקטנות של האתר כבר עוברות.

**הערך בפני עצמו:** ההעלאה הופכת למתחדשת. חיבור שנופל ב-80% של קובץ
8.6MB ממשיך מאותה נקודה במקום מאפס. דורש `tus-js-client`; אינו נוגע
בסוכן.

### דחיסה בדפדפן לפני העלאה

נמדד על הקבצים האמיתיים:

| קובץ | לפני | אחרי | יחס |
|------|------|------|-----|
| GORMEY_KESHER | 3.9MB | 0.7MB | 5.4x |
| PIRTEY_KESHER | 8.6MB | 1.8MB | 4.9x |
| TALMIDIM_AM | 3.2MB | 0.4MB | 7.4x |
| **סה"כ** | **15.9MB** | **3.0MB** | **5.4x** |

כרום דוחס בעצמו דרך `CompressionStream('gzip')`, בלי ספרייה. הקובץ
שנפל יורד ל-700KB, ולסבא זה חמישית מהנפח על חיבור איטי.

**המחיר:** הסוכן צריך לפרוס `.gz` — שינוי בשני הצדדים, כולל בקוד שכבר
נבדק והותקן. לכן נדחה.

## המסקנה

> הודעת שגיאה שלא אומרת **איפה** נכשלה שולחת לחפש באג במקום הלא נכון.

שעה של בדיקות שרת הלכה על תקלה שכלל לא הייתה בשרת. התווית שהוסיפה
"קובץ 1/6, 3.9MB" הצביעה על התשובה מיד — הכשל תלוי גודל, ולכן הוא בדרך
ולא ביעד.

וכשמנפים תקלת רשת: **`<html>` בלי `<!doctype>` אינו האתר שלך.**
