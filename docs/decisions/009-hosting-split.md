# החלטה 009 — האחסון עבר לחשבון של איתי, והריפו התפצל לשניים

תאריך: 2026-08-23
סטטוס: **מאושר, אך זמני** — נועד להתחלף בארגון גיטהאב

## הקשר

המכסה של Netlify אצלי נגמרה. הבאנר בחשבון אמר `You've used over 75% of
your credit allowance` — כלומר **אשראי**, לא תעבורה. האתר הוא 650KB
סטטי וכל הנתונים מגיעים מ-Supabase, אז מה שאוכל את המכסה הוא **בניות**,
לא ביקורים.

לאיתי יש מנוי בתשלום. סבא בפגישת 19.8: *"יאללה, שיתחיל להרוויח את
עצמו."*

## מה ניסינו, ולמה זה לא עבד

התוכנית הייתה: הריפו נשאר אצלי, ה-Netlify של איתי מושך ממנו ישירות.
מקור אמת אחד, שליטה משותפת.

הוספתי את איתי כקולבורייטור. ב-Netlify שלו, בורר הריפואים הציג רק את
הריפואים של `EtaiNir` — שלי לא הופיע.

**הסיבה:** GitHub App מותקן **לכל חשבון בנפרד**. ההתקנה של Netlify אצל
איתי מכסה את הריפואים שלו בלבד. גישת קולבורייטור לריפו אישי של מישהו
אחר לא נחשפת ל-Netlify בצורה אמינה — זו מגבלה מוכרת, לא הגדרה שגויה.

נבדקו והוצעו שלוש חלופות:

| # | חלופה | למה נדחתה |
|---|--------|------------|
| 1 | לרענן את חיבור ה-OAuth של איתי | לא עבד |
| 2 | שאני אצור את האתר בצוות שלו | דורש שיזמין אותי כחבר צוות; לא נבחר בזמן הפגישה |
| 3 | **להעביר את הריפו לארגון גיטהאב** | הפתרון הנכון, אך דורש העברת בעלות וחיבור מחדש — לא בשידור חי |

## ההחלטה

ריפו שני, מראה, בחשבון של איתי:

```
NightKing1234/student-dashboard   מקור האמת. כאן עובדים
        │
        │  git push  (שני push URLs על origin)
        ▼
EtaiNir/Project_Matzevet          מראה. ממנו Netlify בונה
        │
        ▼
https://moonlit-macaron-430f54.netlify.app
```

**הסנכרון אינו ידני.** `origin` הוגדר עם שני push URLs, כך ש-`git push`
אחד מגיע לשני הריפואים:

```bash
git remote set-url --add --push origin https://github.com/NightKing1234/student-dashboard.git
git remote set-url --add --push origin https://github.com/EtaiNir/Project_Matzevet.git
```

זה נבחר על פני GitHub Action שמשכפל: אין טוקן לאחסן, אין חלק נע, ואם
דחיפה לאחד מהם נכשלת — רואים שגיאה מיד.

## למה זה זמני

הבעיה בשני ריפואים היא ש**כל אחד שעובד על הפרויקט חייב להגדיר את
הדחיפה הכפולה בעצמו**. מי שישכח — הקוד יגיע לריפו המקור אבל האתר החי
יפגר, בלי אף שגיאה.

בארגון גיטהאב זה ריפו אחד: התקנת ה-App שייכת לארגון ונחשפת לכל החברים,
ואין דחיפה כפולה בכלל. זה גם פותר את שאלת הבעלות לקראת הגיוס באוקטובר —
לארגון יכולים להיות כמה בעלים, וריפו אישי תלוי בחשבון אחד.

**ההעברה לארגון נדחתה, לא בוטלה.**

## מה אומת בפועל

הפריסה הראשונה נבדקה מול האתר החי, ולא רק "הדף עלה":

|--------|--------|

| `netlify.toml` נקלט | `X-Robots-Tag: noindex` ו-`X-Frame-Options: DENY` בכותרות |
| משתני הסביבה נצרבו | `agcoeqshvkyopjjdvril` נמצא בבנדל |

שלוש הבדיקות האחרונות הן בדיוק המקומות שנפלנו בהם בעבר: `netlify.toml`
שלא נקלט, משתנים שנוספו אחרי הפריסה, ומפתח שנגזר בהדבקה.

## נקודות פתוחות

- **הריפו של איתי נוצר כ-`Public`** ונדחף לפניך שהפך ל-`Private`. אין בו
  סודות — נסרק — אבל יש בו את הסכימה, המיגרציות, ותיאור פרצה שתוקנה.
  להפוך ל-Private.
- **לעצור בניות באתר הישן** (`astounding-pudding-d07e8f`) — כל עוד הוא
  מחובר לריפו, כל דחיפה שורפת אשראי אצלי במקביל.
- **הדומיין** — `moonlit-macaron-430f54` היא כתובת ביניים. היעד הוא
  סאב-דומיין תחת `meiryoffe.co.il`. ה-DNS ב-uPress, אין wildcard,
  ו-`data.` פנוי. **אין לחבר דומיין לפני שהחשבון סגור סופית** — Netlify
  לא מרשה לשני חשבונות לתבוע אותו דומיין.
- **איתי טרם התחיל לעבוד על הפרויקט.** כל עוד זה המצב, אפשר לדחוף בלי
  חשש לדריסה. ברגע שיתחיל — עליו לשכפל מהריפו **שלי** ולהגדיר אצלו את
  אותה דחיפה כפולה.
