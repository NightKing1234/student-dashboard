# ממשק אינטרנטי לניהול נתוני תלמידים — מסמך אפיון מלא

## מטרת המסמך

מסמך זה הוא **הגדרת המשימה הסופית** לבניית ממשק אינטרנטי לניהול נתוני תלמידים ממשרד החינוך. המסמך מכיל את כל מה שצריך כדי לבנות את המערכת — רקע, ארכיטקטורה, פונקציונליות, שדות, ושלבי פיתוח.

---

## 1. רקע

### המצב הקיים

מערכת קיימת מבוססת Microsoft Access משרתת מועצות אזוריות ובתי ספר בישראל. המערכת מנהלת נתוני תלמידים שמתקבלים ממשרד החינוך.

**תהליך העבודה הנוכחי:**

1. משרד החינוך מפיץ מדי חודש קבצי אקסל הנקראים **מצב"ת** (מצבת תלמידים) — 6 קבצים לכל רשות מקומית
2. סקריפט פייתון קיים (8 מודולים) מעבד את הקבצים ומייצר שני קבצי אקסל: קובץ ראשי (~156 שדות, ~5MB) וקובץ תוספתים (חינוך מיוחד)
3. הקבצים נטענים ל-Microsoft Access, שם מפעילים שאילתות, טפסים ודוחות

### מודולי הפייתון (קיימים, לא צריך לבנות)

| מודול | שם | תיאור |
|-------|------|--------|
| 1 | תלמידים | עיבוד ראשוני של נתוני התלמידים — הקובץ הבסיסי |
| 2 | פרטי קשר | חילוץ ועיבוד פרטי קשר של התלמידים והורים |
| 3 | גורמי קשר | עיבוד נתוני גורמי קשר נוספים (הורים, אפוטרופוסים) |
| 4 | מגמות | עיבוד מגמות לימוד — קובץ גדול, עיבוד ארוך |
| 5 | מוסדות | עיבוד נתוני מוסדות החינוך |
| 6 | כיתות | עיבוד נתוני כיתות |
| 7 | השלמות | מעבר על הקובץ הראשי ותיקונים לפי מילונים |
| 8 | תוספתים | זיהוי תלמידי חינוך מיוחד לפי קובץ מוסדות שמתוחזק ידנית |

### המטרה

לבנות **ממשק אינטרנטי** שיחליף את ה-Access ויאפשר למשתמשים (עובדי מועצות אזוריות ובתי ספר) לעבוד עם הנתונים מכל מקום — עם חוויית משתמש מודרנית, סינון חזק, כרטיסי תלמיד מפורטים, וייצוא לאקסל.

### תרשים זרימה

```
קבצי מצב"ת (אקסל)  →  סקריפט פייתון (8 מודולים)  →  מסד נתונים (Supabase)  →  ממשק אינטרנטי (React)
```

## 2. עקרונות מנחים

### הכל ואז מצמצמים
המסך נפתח עם **כל** התלמידים של הרשות. המשתמש מסנן ומצמצם לפי הצורך. לא מתחילים מחיפוש ריק או מחלון פרמטרים — רואים הכל ומשם מצמצמים למטרה.

### רשות = עולם
כל רשות מקומית רואה רק את הנתונים שלה. הפרדה מלאה ברמת מסד הנתונים — **טבלה נפרדת לכל רשות**. הפונקציונליות זהה לכולם, אבל הנתונים מופרדים לחלוטין.

### תצורות שדות (לא מסכים נפרדים)
אין "דפים" נפרדים לתלמידים, הורים, מוסדות. יש **טבלה מרכזית אחת** עם 4 תצורות שדות מוגדרות מראש (presets). כל תצורה מציגה קבוצת שדות שונה כברירת מחדל, ומכל תצורה המשתמש יכול להוסיף/להסיר שדות בחופשיות.

### הכל לאקסל
כל מה שהמשתמש רואה על המסך ניתן לייצוא מיידי לאקסל. גם שדות שחורגים מרוחב המסך (ומוצגים בדפים נוספים) נכללים בייצוא.

## 3. ארכיטקטורה טכנית

### Technology Stack

| שכבה | טכנולוגיה | הערות |
|------|-----------|-------|
| מסד נתונים | Supabase (PostgreSQL) | טבלה ראשית ייחודית לכל רשות, RLS להרשאות |
| אימות | Supabase Auth | כניסה עם מייל/סיסמה, שיוך לרשות |
| צד שרת | Supabase Edge Functions | לוגיקה עסקית, שדות מחושבים |
| צד לקוח | React + Tailwind | ממשק רספונסיבי, RTL מלא |
| אחסון (hosting) | Netlify / Vercel | אירוח הפרונטאנד |
| עיבוד נתונים | Python Pipeline (קיים) | 8 מודולים לעיבוד קבצי מצב"ת |
| ייצוא | SheetJS (xlsx) | ייצוא לאקסל מצד הלקוח |

### מבנה מסד הנתונים

לכל רשות מקומית יש **שתי טבלאות** (בשלב א' רק הראשית):

```
students_14000           →  טבלה ראשית: נתוני משרד החינוך (נדרסת בכל עדכון חודשי)
students_14000_extra     →  טבלת תוספתיים: שדות שהרשות מוסיפה (לא נדרסת) [שלב ד']
users                    →  טבלת משתמשים + שיוך לרשות (משותפת לכל הרשויות)
special_ed_institutions  →  קובץ מוסדות חינוך מיוחד, תחזוקה ידנית [שלב ג']
```

**הטבלה הראשית** מכילה את כל הנתונים שמגיעים ממשרד החינוך אחרי העיבוד בפייתון. בכל עדכון חודשי היא נדרסת לחלוטין. אינדקס ראשי: תעודת זהות.

**טבלת התוספתיים** (שלב ד') מכילה שדות שהרשות מוסיפה ידנית. היא **לא נדרסת** בעדכון חודשי — רק מתעדכנת בדלתא: תלמידים שנגרעו נמחקים, תלמידים חדשים מתווספים (רק ת.ז., בלי נתונים). מקושרת לטבלה הראשית בתעודת זהות.

### אבטחה והרשאות

- **אימות**: כניסה עם מייל וסיסמה דרך Supabase Auth
- **הרשאות שורה (RLS)**: כל משתמש רואה רק טבלאות של הרשויות המשויכות אליו
- **ניהול משתמשים**: מנהל מערכת מוסיף משתמשים ומשייך אותם לרשויות
- **רספונסיבי**: גישה מלאה גם מטלפון נייד

## 5. תצורות שדות (Presets)

הממשק בנוי סביב **טבלה אחת מרכזית**. ארבע תצורות מוגדרות מראש נותנות נקודת פתיחה שונה. מכל תצורה המשתמש יכול להוסיף ולהסיר שדות בחופשיות.

לכל תצורה יש גם **כרטיס** מקביל — לחיצה על שורה פותחת תצוגה מפורטת של אותו תלמיד עם כל השדות הרלוונטיים לתצורה, בעיצוב ידידותי ופונט גדול.

### תצורה 1: תלמידים (ברירת מחדל)

**מיקוד:** מידע פדגוגי ואישי על התלמיד.

**שדות ברירת מחדל:** תעודת זהות, שם משפחה, שם פרטי, מגדר, תאריך לידה, סמל מוסד, שם מוסד, שכבה, כיתה (משולב), שלב חינוך, סוג פיקוח, סוג חינוך מוסד, רשות מוסד, רשות תלמיד, יישוב מגורים, סטטוס תלמיד ברשות.

### תצורה 2: פרטי קשר והורים

**מיקוד:** זיהוי אחים דרך ת.ז. הורה, איתור משפחתי במצבי חירום.

**שדות ברירת מחדל:** תעודת זהות, שם משפחה, שם פרטי, שם מוסד, כיתה (משולב), שם אב, ת.ז. אב, טלפון אב, מייל אב, שם אם, ת.ז. אם, טלפון אם, מייל אם, טלפון בית, כתובת.

**פונקציה קריטית:** זיהוי אחים — לחיצה על ת.ז. הורה מציגה את כל ילדיו במערכת. שימוש קריטי במצבי חירום ואסונות.

### תצורה 3: מוסדות חינוך

**מיקוד:** מיקוד במוסד החינוכי ובמאפייניו.

**שדות ברירת מחדל:** תעודת זהות, שם משפחה, שם פרטי, סמל מוסד, שם מוסד, סוג חינוך מוסד, סוג פיקוח, שלב חינוך, רשות מוסד, שכבה, כיתה (משולב).

### תצורה 4: חינוך מיוחד

**מיקוד:** זיהוי תלמידי משבצת (במוסד חינוך מיוחד) וזכאות (בכיתה רגילה).

**שדות ברירת מחדל:** תעודת זהות, שם משפחה, שם פרטי, סמל מוסד, שם מוסד, סוג חינוך מוסד, סוג כיתה, שכבה, כיתה (משולב), סטטוס חינוך מיוחד, רשות מוסד, רשות תלמיד.

**הסבר חינוך מיוחד:** יש שתי קבוצות שמסמנות תלמיד כחינוך מיוחד:
- **משבצת** — תלמידים שלומדים במסגרת חינוכית של חינוך מיוחד (מוסד חינוך מיוחד או כיתת חינוך מיוחד). נגזר משדות "סוג חינוך מוסד" ו"סוג כיתה".
- **זכאות** — תלמידים שעברו ועדת זכאות אך הוריהם בחרו להשאירם בכיתה רגילה. נגזר מקובץ מוסדות חינוך מיוחד שמתוחזק ידנית.

## 6. פונקציונליות מפורטת

### 6.1 טבלה ראשית

- **פתיחה**: המסך נפתח עם כל התלמידים של הרשות ושדות ברירת המחדל של התצורה הנבחרת
- **מעבר בין תצורות**: כפתורים/טאבים למעבר בין 4 תצורות השדות
- **בורר שדות**: מכל תצורה, המשתמש יכול להוסיף שדות מתוך כלל ~150 השדות הזמינים, או להסיר שדות שלא רלוונטיים לו
- **מיון**: לחיצה על כותרת עמודה ממיינת עולה/יורד
- **לחיצה על שורה**: פותחת כרטיס תלמיד מפורט

### 6.2 דפדוף שדות

כשהמשתמש מוסיף שדות מעבר למה שנכנס ברוחב המסך, הטבלה מתחלקת ל**דפים**:

- בראש הטבלה מופיעים חצי ניווט ומספרי דפים (1, 2, 3...)
- דף 1 מכיל את שדות הליבה/ברירת המחדל
- דפים נוספים מכילים את השדות שהמשתמש הוסיף
- המשתמש מדפדף בין דפים בלחיצה על החצים
- **ייצוא לאקסל תמיד כולל את כל השדות מכל הדפים**

### 6.3 סינון

הסינון עובד על כל שדה בטבלה. אפשר לשלב סינונים על מספר שדות במקביל (AND).

| סוג סינון | תיאור | דוגמה | חל על |
|-----------|--------|-------|-------|
| **שווה** | ערך מדויק | שכבה = "ז" | טקסט |
| **שונה** | הכל חוץ מערך מסוים | סוג פיקוח ≠ "ממלכתי" | טקסט |
| **מכיל** ⭐ | חיפוש חלקי (substring) — **הכלי הכי חזק** | שם מוסד מכיל "מגי" → "מגידו" | טקסט |
| **אינו מכיל** | הכל חוץ ממה שמכיל את הביטוי | שם מוסד אינו מכיל "גן" | טקסט |
| **מתחיל ב** | תחילת הערך — שימושי לקודים וסמלי מוסד | סמל מוסד מתחיל ב "41" | טקסט |
| **מסתיים ב** | סיום הערך | טלפון מסתיים ב "000" | טקסט |
| **גדול מ / קטן מ** | השוואה מספרית או תאריכית | תאריך לידה > 01/01/2012 | מספר / תאריך |
| **בין...ל** | טווח ערכים | תאריך לידה בין 2010 ל-2012 | מספר / תאריך |
| **ריק** | שדות ללא ערך — למציאת מידע חסר | מייל אם = ריק | כללי |
| **לא ריק** | רק שורות שבהן יש ערך בשדה | ת.ז. אב = לא ריק | כללי |
| **אחד מתוך** | בחירה מרובה מרשימה | שם מוסד אחד מתוך ["אלון", "דקל", "ארז"] | כללי |

### 6.4 כרטיס תלמיד

- **הפעלה**: לחיצה על שורה בטבלה
- **תוכן**: כל השדות של התלמיד מאורגנים בקבוצות לוגיות (פרטים אישיים, מוסד, כתובת, הורים...)
- **עיצוב**: פונט גדול, עיצוב קריא וידידותי — מקביל ל"טופס" באקסס
- **ניווט**: כפתורי הבא/הקודם לניווט בתוך תוצאות הסינון הנוכחי (לא כל התלמידים, אלא רק אלה שעברו את הסינון)
- **קישורים**: קישורים ישירים לכרטיס הורים, כרטיס מוסד, מידע חינוך מיוחד
- **מקושר לת.ז.**: אותו אינדקס תעודת זהות כמו הטבלה

### 6.5 ייצוא לאקסל

- **מה מיוצא**: הטבלה הנוכחית עם תמהיל השדות שהמשתמש בחר — כולל שדות מכל הדפים
- **סינון ומיון**: הייצוא משקף את הסינון והמיון הנוכחיים
- **זו הדרך היחידה להפיק דוחות** בשלב א'. אין מחולל דוחות נפרד — המשתמש בונה את תמהיל השדות שהוא רוצה, מסנן, ומייצא לאקסל.

## 7. שלבי פיתוח

### שלב א' — טבלה, כרטיס וייצוא (המוצר המינימלי)

שלב א' הוא עצמאי ונותן ערך מלא. אפשר להשתמש במערכת ברגע שהוא מוכן.

1. הקמת מסד נתונים בענן (Supabase/PostgreSQL) — טבלה ראשית ייחודית לכל רשות
2. מערכת הרשאות: כניסה, ניהול משתמשים, שיוך לרשות
3. טבלה ראשית — פתיחה עם כל תלמידי הרשות ו-~20 שדות ליבה כברירת מחדל
4. תצורות שדות (Presets) — 4 ברירות מחדל: תלמידים, פרטי קשר, מוסדות, חינוך מיוחד
5. בורר שדות — מכל תצורה, המשתמש יכול להוסיף/להסיר שדות בחופשיות
6. דפדוף שדות — כשהשדות חורגים מרוחב המסך, הטבלה מתחלקת לדפים עם חצי ניווט למעלה
7. סינון מתקדם: שווה, שונה, מכיל, אינו מכיל, מתחיל ב, בין...ל, ריק/לא ריק, אחד מתוך רשימה
8. מיון עולה/יורד בלחיצה על כותרת עמודה
9. כרטיס תלמיד — לחיצה על שורה פותחת כרטיס מפורט עם כל השדות
10. ניווט הבא/הקודם בתוך הכרטיס לפי תוצאות הסינון
11. ייצוא לאקסל — כל השדות שהמשתמש בחר, ללא מגבלת רוחב מסך

### שלב ב' — פיבוטים וסיכומים

1. פיבוט: כמה תלמידים בכל מוסד חינוך (ברשות / מחוץ לרשות)
2. פיבוט: פילוח תלמידים לפי שכבה / כיתה בכל מוסד
3. פיבוט: תלמידי חינוך מיוחד לפי מוסד וסוג
4. פיבוט: תלמידים חוצי רשויות — גרים ברשות ולומדים מחוץ לה ולהיפך
5. כל פיבוט ניתן לייצוא לאקסל

### שלב ג' — חינוך מיוחד ושדות מחושבים

1. סימון חינוך מיוחד משבצת — תלמידים במוסד/כיתת חינוך מיוחד
2. סימון חינוך מיוחד זכאות — תלמידים עם זכאות הלומדים בכיתה רגילה
3. שדה כיתה משולב — שכבה + מספר כיתה (למשל: "ז-2")
4. סטטוס תלמיד — גר ברשות / לומד ברשות / חוצה רשויות
5. קובץ מוסדות חינוך מיוחד — תחזוקה ועדכון

### שלב ד' — טבלה תוספתית ועדכון דלתא

1. טבלת תוספתיים — שדות שהרשות מוסיפה ידנית, מקושרת לת.ז.
2. עדכון דלתא — בעת טעינת נתונים חדשים, רק מוחקים תלמידים שנגרעו ומוסיפים חדשים (ת.ז. בלבד)
3. שמירה על נתוני התוספתיים גם כשהטבלה הראשית נדרסת
4. שאילתה משולבת — ראשית + תוספתיים מקושרות בת.ז.

## 9. הערות חשובות למימוש

- **הממשק חייב להיות RTL מלא** — כל הטקסטים בעברית, יישור לימין
- **"מכיל" (contains/substring) הוא הסינון הכי חשוב** — המשתמש רגיל לזה מאקסס ומשתמש בזה כל הזמן
- **אין מחולל דוחות בשלב א'** — הדרך היחידה להפיק דוח היא לבנות תמהיל שדות, לסנן, ולייצא לאקסל
- **בשלב א' עובדים רק עם הטבלה הראשית** (נתוני משרד החינוך) — לא עם טבלת התוספתיים
- **קוד המקור של סקריפט הפייתון נמצא ב-GitHub** — ניתן לקבל גישה מאיתי (המפתח)
- **קיים כבר פיילוט ענן** שאיתי בנה על Supabase + Netlify, עם מסך כניסה, טבלת הרשאות, ותצוגת נתונים בסיסית
